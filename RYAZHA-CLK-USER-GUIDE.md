# Ryazha-clk v3.0.0 — полный гайд по кнопкам и настройкам

> Этот документ объясняет **что делает каждый видимый пункт Ryazha-clk**, где он находится, когда он применяется и от каких условий зависит. Описание проверено по актуальному дереву исходников Ryazha-clk: `Source/hoc-clk/overlay/src/ui/gui/` и `Source/hoc-clk/sysmodule/src/`.
>
> **Важно:** разгон, напряжения, частота экрана, зарядный ток и чиптюнинг могут привести к нестабильности, перегреву или отказу загрузки. Начинайте с `Авто`, меняйте один параметр за раз и проверяйте работу игры. Если настройки KIP сделали систему нестабильной, используйте «Сброс кипа» либо восстановите рабочий `rcu.kip` на SD-карте.

## 1. Как читать меню

| Обозначение | Что означает |
|---|---|
| **A** | Открыть подменю, выбрать значение или переключить пункт. |
| **B** | Вернуться назад без нового выбора. |
| **Y** на CPU/GPU/RAM в профиле или Overrides | Сбросить только эту частоту к `0` — снова действуют нижестоящие правила. |
| **X** на главном экране | Открыть скрытое меню **«Ряженка-Авто»**. |
| **0 / Авто / RCU-Авто** | Не фиксировать ручное значение; решение оставляется таблицам и автоматике Ryazha-clk. |
| **«после перезагрузки»** | Параметр записывается в KIP и полностью вступает в силу после перезапуска консоли. |
| **«живьём»** | Значение уходит в sysmodule по IPC и применяется без перезагрузки. |
| **Справка по пункту** | В меню доступна отдельная справка; она выводит текст, связанный с ключом конфигурации. |

Не путайте **сохранённый профиль**, **глобальный профиль** и **временное значение**. Приоритет простой: временный override действует поверх профиля, профиль игры — поверх общего профиля, а `0` передаёт управление следующему уровню.

## 3. Профиль игры и общий профиль

Каждый профиль содержит отдельные секции для **дока**, **портатива** и поддерживаемых режимов зарядки. Для каждой секции используются одинаковые строки.

| Пункт | Что сохраняется | Поведение |
|---|---|---|
| **ЦПУ** | Целевая частота CPU для текущего режима. | A открывает список реальных доступных частот; Y записывает `0` и возвращает управление общему профилю/автоматике. |
| **ГПУ** | Целевая частота GPU. | Список учитывает выбранную таблицу GPU и реально доступные ступени. |
| **РАМ** | Целевая частота памяти EMC. | Не задаёт VDD2/VDDQ сам по себе: ручные напряжения памяти не затираются. |
| **Дисплей** | Целевая герцовка профиля. | Появляется только если включено «Менять частоту обновления». Ограничения зависят от LCD/OLED, дока и режима Retro. |
| **Говернер** | Режимы governor для CPU, GPU и VRR. | Упакован в одно поле профиля: `Не менять`, `Выкл`, `Вкл`; у VRR есть четвёртый режим **VRR-Авто**. |

### Governor в профиле

| Строка | Режимы | Значение |
|---|---|---|
| **ЦПУ** | Не менять / Выкл / Вкл | Включает или отключает управление CPU-governor для данного профиля. |
| **ГПУ** | Не менять / Выкл / Вкл | То же для GPU-governor. |
| **VRR** | Не менять / Выкл / Вкл / VRR-Авто | Управляет VRR данного профиля. Строка появляется, когда разрешена перезапись частоты дисплея либо включен режим Retro. |

Код профиля пишет изменения через `hocclkIpcSetProfiles`; поэтому профиль остаётся после перезапуска. Логика экрана и packed governor находится в `app_profile_gui.cpp:296–501`.

## 4. Временные значения

**Временные значения** повторяют CPU/GPU/RAM/Display/Governor, но работают иначе.

| Пункт | Что происходит |
|---|---|
| **ЦПУ / ГПУ / РАМ** | A задаёт частоту только на текущий запуск. Y сбрасывает override в `0`. |
| **Дисплей** | Если разрешена смена герцовки, ползунок отправляет временный Hz через `hocclkIpcSetOverride`. |
| **Governor** | Временно задаёт CPU/GPU/VRR governor; профиль не переписывается. |

Это правильное место для проверки, выдержит ли конкретная игра частоту, прежде чем сохранять её в профиле. Реализация использует `hocclkIpcSetOverride`, а не `hocclkIpcSetProfiles` — см. `global_override_gui.cpp:327–439`.

## 5. Настройки → Разгон → ЦПУ

### Частота и потолок

| Пункт | Ключ / диапазон | Что делает |
|---|---|---|
| **Частота ЦПУ** | `commonCpuBoostClock`, до 2907 МГц | Выбирает потолок CPU DVFS-лестницы после перезагрузки. Список фильтруется по реальному доступному напряжению: недостижимые точки не предлагаются. |
| **Макс. вольтаж ЦПУ** | `marikoCpuMaxVolt`, Авто или 1130–1375 мВ | Верхняя граница CPU-рейла. При выборе более высокой частоты меню автоматически поднимает потолок как минимум до требуемого значения. Понижение потолка принудительно ограничивает ручной Vmin, чтобы минимум не стал выше максимума. |
| **Мин. вольтаж ЦПУ** | `CPUv` | Выбирает источник нижнего напряжения CPU: авто по RAM, авто с −20/−40 мВ или собственная таблица. |
| **Задать вручную (мВ)** | то же поле `CPUv` | Ручной Vmin CPU. Работает вместо предыдущего пункта, ограничивается потолком CPU и диапазоном 500–1000 мВ. На высокой RAM sysmodule может поднять его до обязательного пола. |
| **DVCO верх** | `marikoCpuHUV`, 0–12 | Верхняя ступень CPU DVCO. `0` — автоматический выбор. Более высокая ступень открывает высокие CPU-точки, но требует достаточного потолка напряжения. |
| **DVCO низ** | `marikoCpuUV`, 0–12 | Нижняя ступень CPU DVCO. Обычно оставляется `0`: ненулевое значение меняет CPU-таблицу и не является обычным способом разгона. |
| **Логика Min-High ЦПУ** | `dCPUv`, 0–3 | Выбирает режим внутренней автоматической логики Vmin CPU. |
| **Андервольт низа ЦПУ** | `SpeedShift` | Сдвигает нижнюю часть CPU-таблицы. Допустимы только готовые кратные 25 мВ варианты; произвольные шаги не используются, так как нарушают сетку загрузочной таблицы. |

### CPU и RAM связаны

При разгоне памяти sysmodule вычисляет **минимальный безопасный пол CPU по частоте RAM**. Поэтому ручное низкое напряжение CPU не всегда применяется буквально: если оно ниже обязательного пола для текущей EMC-частоты, sysmodule поднимет его на лету. Экран «Таблица вольтажа ЦПУ» показывает этот пол в подсказке.

| Пункт | Что делает |
|---|---|
| **Включить буст от РАМ** | При RAM выше заданного порога удерживает CPU на выбранной частоте. Система отключается, если используется Ряженка-Авто, чтобы две автоматики не спорили. |
| **Порог РАМ** | RAM-частота, после которой включается CPU-буст. `Авто` выбирает середину реальной лестницы памяти данной консоли. |
| **Бустить ЦПУ до** | Частота CPU, которую механизм RAM→CPU будет удерживать при срабатывании. |
| **Таблица вольтажа ЦПУ** | Открывает 24 частотные точки 510–2907 МГц. Каждая точка имеет окно около дефолта; запись идёт в KIP. Низкие точки могут быть подняты обязательным полом RAM. |

Исходник: `misc_gui.cpp:842–1177`, `misc_gui.cpp:1688–1760`.

## 6. Настройки → Разгон → ГПУ

Эти пункты относятся к **Mariko GPU**. Они формируют частотную/вольтажную таблицу GPU и применяются после перезагрузки, кроме таблицы ручного режима.

| Пункт | Что делает | Важная зависимость |
|---|---|---|
| **Режим ГПУ** | Выбирает доступную GPU-таблицу: до 1459, 1536, 1766 МГц либо «Ручная таблица». | «Ручная таблица» использует отдельную таблицу напряжений GPU. |
| **Кривая вольтажа** | Выбирает автоматическую форму кривой или ручную нижнюю точку 500–900 мВ. | Не действует, если «Режим ГПУ» = «Ручная таблица». |
| **Вольтаж вершины** | Задаёт напряжение верхней GPU-точки: Авто либо 750–1200 мВ. | На высоких частотах зависит от качества чипа; не заменяет «Потолок рейла». |
| **Потолок рейла** | Верхняя граница GPU-рейла. При Авто используется стоковая граница около 1050 мВ. | Точки выше практического лимита sysmodule всё равно ограничивает; ручная таблица не может выйти за допустимый диапазон. |
| **Пол вольтажа** | Нижняя граница Vmin GPU; Авто или 300–900 мВ. | Нельзя задать точку ручной таблицы ниже этого пола. |
| **UV нижней точки** | Уменьшает нижнюю часть GPU-кривой на 5–45 мВ. | Не работает в «Ручной таблице». |
| **UV вершины** | Уменьшает верхнюю часть GPU-кривой на 5–45 мВ. | Не работает в «Ручной таблице». |
| **Таблица вольтажа ГПУ** | 31 ручная точка от 307 до 1766 МГц. | Предназначена для «Ручной таблицы». Диапазон каждого ползунка ограничен полом и потолком GPU-рейла. |
| **Сбросить к кривой RCU** | Восстанавливает все 31 точки к дефолтам RCU. | Применяется через IPC сразу для ручной таблицы. |

Исходник: `misc_gui.cpp:1180–1273`, `misc_gui.cpp:1613–1680`.

## 7. Настройки → Разгон → РАМ, DVFS и напряжения памяти

### Частота RAM

| Пункт | Что делает |
|---|---|
| **Макс. частота РАМ** | Задаёт максимальную частоту EMC после перезагрузки. Выбор частоты **не перезаписывает** ваши ручные VDD2/VDDQ. При `Авто` лоадер использует собственный подбор. |
| **Тайминги MTC** | Выбирает: автонастройку, свои поправки, не менять тайминги или собственную таблицу. |
| **Запас записи** | Увеличивает вклад в `nWR`: выше значение обычно свободнее и стабильнее, но не быстрее. |
| **Ужатие записи** | Вычитает вклад из `nWR`: выше значение сильнее ужимает запись и увеличивает риск. |
| **Тайминги памяти** | Открывает расширенные тайминги, pMEH/sMEH и SHAITAN. Это экспертная зона. |

### Живой вольтаж — это DVFS / PCV Hijack

> **«Живой вольтаж» — не просто отображение.** При включении он переводит `DVFSMode` в `PCV Hijack`: sysmodule перед повышением EMC применяет VDD2/VDDQ для целевой ступени RAM и корректирует связанный Vmin GPU. При выключении используются общие VDD2/VDDQ, а по-частотная таблица скрывается.

| Состояние | Какие пункты доступны | Как работает |
|---|---|---|
| **Живой вольтаж = Выкл** | **VDD2 памяти**, **VDDQ шины**, **Вольтаж SoC** | Одно глобальное значение VDD2/VDDQ действует на все частоты памяти. `Авто` даёт лоадеру подобрать напряжение. |
| **Живой вольтаж = Вкл** | **Сдвиг Vmin ГПУ при RAM**, **Таблица вольтажа РАМ**, **Вольтаж SoC** | VDD2/VDDQ выбираются отдельно для текущей ступени EMC. Общие VDD2/VDDQ намеренно скрываются, потому что в этом режиме не участвуют. |

| Пункт | Что делает |
|---|---|
| **Сдвиг Vmin ГПУ при RAM** | Новый видимый `DVFSOffset`. Сдвигает рассчитанный Vmin GPU при переходе частоты RAM в режиме PCV Hijack. Диапазон UI: **−80…+80 мВ**, шаг 5 мВ; `0` — без сдвига. Вне «Живого вольтажа» пункт скрыт и не работает. |
| **VDD2 памяти** | Глобальное питание памяти при выключенном живом режиме. Сетка физического преобразователя — 12,5 мВ; `Авто` рекомендуется по умолчанию. |
| **VDDQ шины** | Глобальное питание интерфейса DRAM при выключенном живом режиме. |
| **Вольтаж SoC** | Глобальный сдвиг/ручное значение SoC. Сам секвенсер уже использует собственную по-частотную DVB-таблицу. |
| **Таблица вольтажа РАМ** | При включённом живом режиме показывает реальные доступные частоты памяти. Для каждой ступени есть пара **VDD2** и **VDDQ**. `Авто` в ячейке возвращает авто-брекет. |

Пофреквенционная таблица содержит до 16 ступеней — это ограничение формата конфигурации. VDD2 в таблице начинается с 1125 мВ, VDDQ — с 500 мВ: более низкие значения sysmodule всё равно ограничил бы до физического пола.

Исходник: `misc_gui.cpp:1276–1472`, `misc_gui.cpp:1762–1821`, `clock_manager.cpp:669–717` и `clock_manager.cpp:962–1044`.

## 8. Настройки → Разгон → Чиптюнинг

Чиптюнинг меняет параметры DC/DC-преобразователей. Он не нужен для обычного разгона и должен оставаться выключенным, если нет конкретной причины и проверки стабильности.

| Пункт | Что делает |
|---|---|
| **Включить** | Глобально включает применение параметров чиптюнинга. Без него остальные значения не должны рассматриваться как активная настройка. |
| **Прямой ШИМ** | Переводит соответствующий рейл CPU/DRAM/GPU в режим forced PWM. На Mariko имеются отдельные CPU M4, DRAM M3 и GPU M1; на Erista — отдельные CPU/GPU-переключатели. |
| **Лимит тока** | Пиковый лимит выбранного рейла. В UI значения 7,2 A и 8 имеют предупреждающие пороги. |
| **Частота ШИМ** | Частота переключения преобразователя: Авто или 1,0–2,5 МГц. |
| **Компенсация петли** | Включает компенсацию управляющей петли для рейлов. |
| **Скорость** | Профиль скорости нарастания напряжения всех рейлов: Авто, 5/10/20/40 мВ/мкс. Агрессивные варианты могут усиливать переходные процессы. |
| **Напряжение картриджа** | Питание GCA: Авто либо 2800–3300 мВ; 3100 мВ отмечено как HOS default. |

Исходник: `misc_gui.cpp:1825–1918`.

## 9. Настройки → Экран / VRR

| Пункт | Что делает | Условия |
|---|---|---|
| **Менять частоту обновления** | Разрешает профилям и Overrides менять Hz дисплея. | Без него не появятся строки Display/VRR в нужных местах. |
| **Настройки VRR-Авто** | Открывает параметры умного VRR. Сам режим включается в профиле или Override → Governor → VRR → **VRR-Авто**. | Нужен SaltyNX для FPS; только портатив. |
| **Макс. Гц (портатив)** | Верхняя граница ручной портативной герцовки. | LCD: до 75 Гц; OLED/Aula: консервативный экранный диапазон. Несовместимые значения могут повредить матрицу. |
| **Вольтаж дисплея** | Напряжение панели 800–1200 мВ. | Скрыто на Aula; риск для LCD-панели. |

### VRR-Авто

| Пункт | Что делает |
|---|---|
| **Мин. Гц / Макс. Гц** | Нижняя и верхняя границы, внутри которых VRR следует за FPS. LCD использует 40–75 Гц; OLED имеет собственные ограничения. |
| **Агрессивность** | Насколько охотно предиктор меняет герцовку. |
| **Порог скачка** | Разница FPS, которую алгоритм считает резким изменением. |
| **Запас над FPS** | На сколько Гц держать дисплей выше измеренного FPS. |
| **Задержка понижения** | Сколько тиков ждать перед снижением Hz, чтобы герцовка не прыгала на кратких просадках. |

## 10. Настройки → Общие, Говернер и Безопасность

### Общие настройки

| Пункт | Что делает |
|---|---|
| **Вольтаж РАМ: показ** | На Mariko выбирает, какое значение RAM показывать в интерфейсе: VDD2 или VDDQ. На питание не влияет. |
| **Единицы частоты РАМ** | Форматирует отображение памяти как МГц, MT/s или оба варианта. На частоту не влияет. |
| **Интервал опроса** | Частота обновления информации sysmodule/оверлеем: 50–1000 мс. Меньше интервал — чаще опрос и выше служебная нагрузка. |

### Говернер

| Пункт | Что делает |
|---|---|
| **Мин. частота ЦПУ** | Нижняя частота, которую CPU-governor будет удерживать при включённом governor. Доступны 510–1020 МГц. Это не фиксированная частота и не разгонный потолок. |

### Безопасность

| Пункт | Что делает |
|---|---|
| **Снять потолки частот** | Убирает программные ограничения частот. Использовать только после проверки остальных напряжений, температур и таблиц. |
| **Сброс при перегреве** | Включает защитный сброс/откат при превышении температуры. Рекомендуется держать включённым. |
| **Порог троттлинга** | Температура 50–85 °C, после которой начинает работать тепловая защита. Порог 70+ помечается предупреждением. |

Исходник: `misc_gui.cpp:1920–1967`, `misc_gui.cpp:2081–2105`, `misc_gui.cpp:2320–2343`.

## 11. Экспериментальные функции

Сначала на странице **Настройки** включите **«Экспериментальные функции»**. Только после этого появляется **«Открыть раздел»**.

| Пункт | Что делает | Ограничение |
|---|---|---|
| **Mariko Middle Frequencies** | Включает промежуточные ступени частот Mariko. | Только Mariko. |
| **Live CPU UV** | Включает экспериментальный живой undervolt CPU. | Только Mariko; требует особенно осторожной проверки. |

| **Измерение частоты РАМ** | Источник измерения EMC: PLL либо Actmon. | Влияет на измерение/отчёт, не является разгоном напрямую. |

## 12. Ряженка-Авто: авторазгон по FPS

Открывается **X с главного экрана**. Это отдельный автоматический режим, а не постоянный профиль частоты.

| Пункт | Что делает |
|---|---|
| **Включить авторазгон** | Включает движок Auto OC. Без валидного FPS от SaltyNX он не может правильно подбирать частоты. |
| **Целевой FPS** | Цель алгоритма: 30, 45, 60 или верхний режим панели. |
| **Допуск (кадров)** | Допустимое отклонение FPS от цели до следующего изменения частот. |
| **Алгоритм** | `Цикл` или `Смарт` — стратегия подбора частот. |
| **Лимит темп. ЦП / ГП** | Ограничения, которые важнее цели FPS. При достижении авторазгон снижает нагрузку. |
| **Лимит TDP** | Предел мощности: Авто либо 5–12 Вт. Он также важнее цели FPS. |
| **Мин./Макс. ЦП** | Нижняя и верхняя границы CPU, внутри которых автоматике разрешено искать частоту. |
| **Мин./Макс. ГП** | То же для GPU. |
| **Держать РАМ на максимуме** | Не позволяет автоматике отпускать RAM ниже максимума. Увеличивает нагрузку и может быть излишним для лёгких игр. |

Скрытый вход и UI: `main_gui.cpp:127–137`, `misc_gui.cpp:2186–2278`. Сам алгоритм расположен в `sysmodule/src/mgr/auto_oc.cpp`.

## 13. Расширенные тайминги и экспертные таблицы

Эти пункты не являются готовыми пресетами. Они напрямую меняют поля таблиц памяти и применяются пользователю, который понимает назначение каждого тайминга.

| Раздел / кнопка | Что меняется |
|---|---|
| **Тугость таймингов** | Главный уровень, который включает группы ужесточений MTC. Выше = обычно ниже задержки, но выше риск. |
| **tRCD / tRP / tRAS** | Прямое уменьшение соответствующих RAM-таймингов в циклах. |
| **SRPD / WL набор** | Дополнительные параметры self-refresh/write leveling. |
| **База RCD/RP/RAS, База 2–4** | Индексы базовых таблиц таймингов. |
| **tRCDw / tWTR / tRTW / tWTP** | Сдвиги конкретных таймингов записи/чтения. |
| **Тонкая настройка (pMEH)** | Живые микро-параметры: nWR, запись, чтение, tRTW, tWTR, tWTP, divMB, вариант DVB, PLL divN, релакс и запас EMC-брекета. |
| **Вторичные тайминги (sMEH)** | ARB, latency, eZQ, tr DVFS, DBI, refresh, MRS и SSC. |
| **SHAITAN** | Ручной сплайсер PCV. Используется только для адресного патчинга слов PCV: число активных сплайсов, поиск, смещение, ожидаемое слово и замена. При нулях ничего не патчит. |

Исходник намеренно не показывает мёртвые слоты массивов. Это не «пропавшие настройки»: строки, которые лоадер не читает, скрыты, чтобы пользователь не менял неработающие значения. См. `misc_gui.cpp:1475–1610`.

## 14. Быстрые ответы на частые вопросы

| Вопрос | Короткий ответ |
|---|---|
| Где DVFS? | **Разгон → РАМ → Живой вольтаж**. Это переключатель PCV Hijack/DVFS. |
| Где GPU Vmin, зависящий от RAM? | При живом вольтаже: **Сдвиг Vmin ГПУ при RAM**. Базовый пол GPU находится в **Разгон → ГПУ → Пол вольтажа**. |
| Почему нет VDD2/VDDQ? | Включён живой вольтаж: вместо общих значений используйте **Таблицу вольтажа РАМ**. |
| Почему «Кривая вольтажа» GPU не меняет ничего? | Проверьте, не выбран ли **Режим ГПУ → Ручная таблица**: в нём кривая отключается. |
| Почему значение CPU ниже не применяется? | Высокая RAM может поднять CPU до обязательного пола по памяти. |
| Как быстро проверить частоту? | Используйте **Временные значения**, а не профиль игры. |
| Как вернуть частоты профиля? | На строке CPU/GPU/RAM нажмите **Y**; значение станет `0`. |
| Как сбросить KIP-настройки? | **Настройки → Сброс кипа**. Это сбрасывает пакет Ryazha-контролов к дефолтам. |
